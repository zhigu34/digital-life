# 追剧页面 V2 设计

## 目标

在现有独立追剧模块上补齐作品元数据和观看完成信息，并重做卡片信息层级、表单编辑能力和按媒体类型分组展示。保持现有 `/api/shows` CRUD、封面代理/上传和用户隔离模型，不引入新的子系统。

## 数据模型

`shows` 新增三个可空字段：

- `release_year: int | null`：上映/首播年份，允许手工编辑；刮削时从提供方的日期提取。
- `completed_on: date | null`：看完日期。记录第一次从非 `completed` 进入 `completed` 时，若该字段为空则由后端按用户请求当天自动填写；已有值不覆盖。用户可以之后手工修改或清空。
- `source_url: str | null`：实际采用的刮削来源作品页 URL，用于页面标题外链，也允许手工清空/修正。

SQLite 启动迁移沿用项目现有兼容升级方式，为旧数据库安全添加 nullable 列，不要求用户手工迁移。

## 元数据刮削

Bangumi/TMDB 搜索结果增加 `release_year` 和 `source_url`：

- Bangumi：从 `date` 提取年份，来源页为 `https://bgm.tv/subject/{source_id}`。
- TMDB：从 `first_air_date` / `release_date` 提取年份；TV 链接为 `https://www.themoviedb.org/tv/{source_id}`，电影为 `https://www.themoviedb.org/movie/{source_id}`。

新增和编辑状态都允许重新搜索、重新应用元数据。应用结果可更新标题、总集数、来源、来源 ID、来源链接、封面、季数、播出状态和上映年份；不得覆盖用户的观看进度、观看状态、评分、备注、更新日或看完日期。

## 表单

`ShowForm` 改为分区式详情编辑器：基础信息、观看信息、作品信息/刮削、封面、备注。

剧集和动漫显示进度、总集数、季数、更新日；电影隐藏这些剧集字段。所有类型都可编辑观看状态、评分、上映年份和看完日期。来源区域展示来源、来源 ID 和来源链接；存在 URL 时可直接打开来源页。

当用户在表单中选择“已看完”但没有 `completed_on` 时，前端可以即时显示当天作为默认值以提供清晰反馈；最终自动填充规则仍由后端保证，避免绕过 UI 的 API 更新产生不一致。

## 卡片

卡片第一层为封面、标题、主状态和媒体类型。存在 `source_url` 时标题是外链并在新标签页打开；编辑入口保留在封面/独立编辑交互上，避免标题同时承担编辑和跳转两个动作。

剧集/动漫卡片突出 `已看 X / Y 集`、进度条和紧凑 `+1 集` 操作，并在次要信息中显示季数、上映年份、更新日、播出状态。电影卡片不显示集数进度和 `+1`，显示上映年份、观看状态以及存在时的看完日期。评分继续作为高识别度信息；备注最多两行，避免卡片高度被长文本撑开。

## 页面分组与筛选

保留现有状态 Tab 和搜索。过滤完成后按固定顺序 `剧集 → 动漫 → 电影` 分组，每组显示标题、数量和自己的响应式卡片网格；空组隐藏。搜索和状态筛选同时作用于全部分组，不增加第二套类型 Tab。

## 兼容与安全

旧记录的新字段均为 `null`，继续正常展示和编辑。`source_url` 作为普通 HTTPS 外链保存；前端外链使用 `target="_blank"` 与 `rel="noopener noreferrer"`。后端限制 URL 长度并只接受 `http/https`，避免把任意脚本协议写入可点击标题。

## 验证

后端测试覆盖新增字段 CRUD、旧库迁移、首次完成自动日期且不覆盖已有日期、URL 校验，以及 Bangumi/TMDB 的年份和来源链接。前端单测覆盖 payload/metadata patch 和分组；E2E 覆盖新增与编辑、重新刮削、标题外链、电影/剧集字段差异、类型分组、搜索/状态筛选组合以及桌面/移动端关键交互。完整 CI 必须通过后才合并到 `main`；NAS 部署仍由用户执行。
