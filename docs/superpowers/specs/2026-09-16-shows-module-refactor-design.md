# 追剧模块独立化设计（用户已确认方向，2026-09-16）

目标：在不改变现有 `/api/shows` 数据模型、数据库迁移和后端接口语义的前提下，把追剧从通用集合页面/表单中拆成独立前端模块，为后续观看历史、季度/剧集详情等功能留出清晰边界，同时保持当前桌面与手机体验、账号隔离和已有数据完全兼容。

## 当前问题

- `frontend/src/views/CollectionView.vue` 同时承担待办、周期费用、追剧和重要日子四种业务。追剧已经包含独立统计、状态筛选、封面、评分、媒体类型、季数、连载状态、更新星期、进度与“看完一集”等逻辑，继续叠加会让通用页面越来越难维护。
- `frontend/src/components/RecordForm.vue` 同时承担多种记录表单，追剧又额外包含 Bangumi/TMDB 搜索、元数据回填、封面 URL、本地上传、季数/总集数/状态等专属交互。
- 当前后端能力已经足够：`/api/shows` CRUD、元数据搜索、`PUT /api/shows/{id}/poster` 本地封面上传和 `GET /api/shows/{id}/poster` 代理/本地读取均保持不变，本轮没有必要引入新迁移或 API。

## 架构拆分

### `ShowsView.vue`

新增 `frontend/src/views/ShowsView.vue`，负责完整追剧页面：

- 页头与作品数量；
- 追剧统计卡片：在看、想看、已看完、暂搁、累计看完集数；
- 状态筛选和标题搜索；
- 空状态；
- 作品列表；
- 向父层只发出既有 `create`、`edit`、`action` 事件，不直接拥有全局数据请求。

`App.vue` 在当前页面为 `shows` 时渲染 `ShowsView`；其他通用集合继续使用 `CollectionView`。这样数据加载、保存、删除和错误处理仍由现有顶层流程统一管理，不复制 API 状态管理。

### `ShowCard.vue`

新增 `frontend/src/components/ShowCard.vue`，只负责一个 `Show` 的展示和快速操作：

- 封面点击进入编辑；
- 评分、状态、媒体类型、季数、连载/完结状态、更新星期；
- 标题和备注；
- 当前进度与总集数；
- “看完一集”按钮及达到总集数后的禁用；
- 进度条。

组件通过事件把 `edit` 和 `advance` 交回 `ShowsView`，不直接调用 API。

### `ShowForm.vue`

新增 `frontend/src/components/ShowForm.vue`，承接 `RecordForm.vue` 当前所有追剧专属 UI 和状态：

- 标题、媒体类型、状态、进度、总集数、评分、备注；
- 更新星期、季数、连载状态；
- Bangumi/TMDB 源切换、关键词搜索、候选展示与回填；
- 远程封面预览；
- 编辑态本地封面上传、清除与上传状态；
- 保存时输出与现有 `Show` payload 兼容的数据。

`RecordForm.vue` 保留 tasks/expenses/milestones 的通用记录表单，不再包含追剧条件分支。追剧编辑弹窗在 `App.vue` 中改为挂载 `ShowForm`，删除按钮和现有确认流程保持原样。

## 数据与接口兼容性

- 不新增 Alembic 迁移。
- 不修改 `Show` 表字段。
- 不修改 `/api/shows` CRUD 的请求或响应结构。
- 不修改元数据搜索接口和 poster 上传/读取接口。
- `poster_path = "local:upload"` 的本地封面语义保持不变。
- 现有 NAS SQLite 数据无需转换，升级只涉及前端构建产物。

## 交互保持与改进

- 现有状态筛选：全部 / 在看 / 想看 / 已看完 / 暂搁，语义不变。
- 搜索仍按标题即时过滤。
- 点击封面仍打开编辑弹窗。
- “看完一集”仍调用现有 `advance` action，不改变自动推进逻辑。
- 桌面继续使用紧凑横版卡片；手机继续单列和较窄封面，触控按钮不得小于现有可用尺寸。
- 追剧独立后移除 `CollectionView` 中 shows 专属模板和统计逻辑，避免存在两套 UI 实现。

## 错误与状态处理

- 元数据搜索失败、poster 上传失败继续沿用现有表单内就地错误提示；拆分后不吞掉后端 `detail`。
- `busy` 状态继续由顶层传入，保存、删除、推进集数时防止重复提交。
- 图片加载失败不影响卡片主体；没有封面时继续显示 shows 图标占位。
- 筛选/搜索结果为空时显示现有空状态，不修改记录数据。

## 测试

### 前端单元/组件测试

新增或调整 Vitest 覆盖：

- `ShowsView` 状态筛选与标题搜索；
- `ShowCard` 正确展示 metadata、进度和评分；
- 已达到总集数时“看完一集”禁用；
- 点击封面发出 edit，点击推进发出 advance；
- `ShowForm` 元数据候选回填后生成与现有保存接口兼容的 payload；
- 编辑态上传/清除封面事件保持既有行为。

### 浏览器回归

Playwright 至少覆盖桌面和手机：

1. 新增作品；
2. Bangumi/TMDB 搜索回填；
3. 编辑既有作品；
4. 上传本地封面后列表可见；
5. 点击封面再次进入编辑；
6. 看完一集后进度刷新；
7. 状态筛选和搜索；
8. 删除作品；
9. 刷新后数据仍存在；
10. 第二账号不可读取第一账号作品。

后端本轮不改业务逻辑，但完整 CI 仍需跑 pytest、Ruff、Vitest、前端 build 和 Docker/Playwright 流程，确保拆分未造成契约回归。

## 非目标

本轮不加入观看历史、单集列表、季度详情、自动同步更新、推送提醒、新数据源、评分平台同步或新的统计口径；这些能力在模块边界稳定后再单独设计。
