# 统一日历视图设计（用户已确认）

目标：新增「日历」页面，把待办截止日、周期费用扣费日、维护到期日和重要日子集中到同一张月历里，点击日期查看当日安排并可跳转对应页面。纯派生视图，不新增数据表和接口。

## 范围与边界

- 数据全部来自已加载的 tasks/expenses/milestones/maintenance，服务端不改动。
- 事件语义与既有页面严格一致：
  - 待办：未完成且有截止日的才显示；早于今天的标记逾期。
  - 费用：仅启用中的费用；扣费日从 next_due 按整周期外推（与「本月应付」同语义，不假设已支付），保留月末 anchor（1/31 → 2/28 → 3/31）。
  - 重要日子：每年重复的在目标年月按日号显示（闰日平年钳到 2/28）；单次只在精确月份显示。
  - 维护：仅启用中的事项，显示 next_due 单日；早于今天标记逾期。
- 周期只有 1/3/12 个月（服务端 Literal），外推循环有界。

## 交互

- 桌面侧栏与手机底部导航新增「日历」（第二项，导航变 7 列）。
- 月历周一开头，前置/尾置显示相邻月灰色日期；上/下月与「今天」按钮导航，默认选中今天。
- 格子显示日期、最多 2 个彩色标签（超长省略号）、「还有 N 项」；图例显示各类当月计数。
- 当日面板列出事件（图标、标题、逾期标记、金额/优先级等摘要），点击行跳转对应页面。

## 验证

- `frontend/src/calendar.ts` 纯函数（月格子、费用外推、里程碑钳制、事件汇总排序）配套 Vitest。
- Playwright 桌面/手机用例：创建当月待办、费用、每年日子后进入日历，断言格子标签、当日面板、跳转、翻月、「今天」复位与无横向溢出。
