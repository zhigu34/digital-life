# JSON 导入设计（用户已确认）

目标：支持把个人导出的 JSON 恢复进账号，用于迁移或误删恢复。与导出形成闭环。

## 行为

- `POST /api/import`（会话 + CSRF + Origin 校验）接收 `/api/export` 的完整对象，**整体替换**当前账号的生活记录：tasks、expenses、shows、milestones、maintenance 及 maintenance_logs。
- 不修改登录、密码、个人资料（display_name/时区/主题等），不影响其他账号。
- 集合列表缺失按空处理：兼容周期维护上线前的旧导出；但要求顶层 `user` 对象作为"本产品导出"的标记，且至少一条记录，否则 422。
- 逐条按创建接口的校验规则验证（长度、字面量、整数范围）；行内多余键（id、created_at、next_due 等服务端字段）忽略并重新分配。首条无效即 422，事务回滚，现有数据不动。
- 维护导入：按导出 id 把历史挂回事项；事项的 `last_completed`/`next_due` 一律从导入历史重算（不信任导出值）；每个事项至少保留一条历史（无历史时按 last_completed 合成创建式记录）；同日重复历史、悬空引用、重复/缺失事项 id 均 422。
- 上限：单集合 10,000 条、总数 50,000 条。

## 界面

- 个人设置「你的数据」面板新增「导入数据」：选择 JSON → 弹窗展示各集合条数预览与替换警示 → 「替换并导入」。错误（非 JSON、非本产品导出）就地提示。

## 验证

- pytest：CSRF 缺失 403、完整往返（含维护历史重算与重复导入不翻倍）、旧版格式、六类非法输入 422、失败导入不动现有数据、双账号隔离。
- Playwright：真实文件选择 → 预览 → 确认 → 新账号看到导入待办且旧待办被替换。
